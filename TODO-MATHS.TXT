Development order

I suggest we actually implement it in these stages:

Stage 1 — Contracts

schemas.py, api.py, package exports.

Stage 2 — Task representation

Canonical task signatures and feature extraction.

Stage 3 — History

Store/load observations and approval outcomes.

Stage 4 — Mathematical models

PMF → PDF → risk → Jacobian → Hessian.

Stage 5 — Decision geometry

Safe region, uncertain region, risky region, and the experimental safe-route mechanism.

Stage 6 — Engine

Combine the components behind one public API.

Stage 7 — Unit tests

Test every component independently, including pathological inputs.

Stage 8 — Simulation

Generate hundreds/thousands of READ_TABLE → CALCULATE tasks and see whether the model actually separates known-safe, novel, and risky cases.

Stage 9 — Only if the results justify it

Create the tiny filesystem adapter.

And one thing I want to be particularly strict about: we won't manufacture impressive-looking confidence numbers. If the model has insufficient data, its API should explicitly return something like INSUFFICIENT_EVIDENCE / HUMAN_REVIEW.

That will make this a genuine experiment rather than simply dressing a conventional rule engine up with mathematical terminology.
